# PAOS Pipeline System

> Pipeline lifecycle, directory structure, phase execution, and known issues.
> See also: [API Reference](api.md#3-pipelines), [Usage Examples](examples.md#2-cross-agent-pipeline).

## Concept

A **pipeline** is a multi-phase workflow executed by different agents in dependency order. Phases can be linear (n1 → n2) or DAG-based (parallel branches with dependencies). Pipelines are created from the CLI (`h-pipeline`), the dashboard UI (Flow Builder), or via the API.

## Pipeline Lifecycle

```
Created → Submitted → Executing (phase-by-phase) → Completed / Failed
```

1. **Created** — `POST /api/pipelines` or `h-pipeline submit`. Generates a PIPE-ID and directory scaffold.
2. **Submitted** — Pipeline lands in the queue. Systemd watcher or manual `h-pipeline execute` picks it up.
3. **Executing** — The executor dispatches phases in topological order. Each phase spawns an agent, which produces artifacts in its phase directory.
4. **Completed** — All phases done. Status files updated. WALKTHROUGH.md written.

## Directory Structure

Each pipeline lives at `logs/pipelines/PAOS/<PIPE-ID>/`:

```
<PIPE-ID>/
├── META.json            # Metadata: id, prompt, phases list, per-phase status & artifacts
├── pipeline.json        # Live runtime status (currentTask, progress, startedAt)
├── TASKS.md             # Top-level task list (one line per phase)
├── pipeline-flow.json   # DAG definition: phase nodes, edges, agent assignments, order
├── builder-layout.json  # Flow Builder UI layout (node positions, edge types, React Flow data)
├── phases/
│   ├── n1/              # Phase-specific directory
│   │   ├── IMPLEMENTATION.md  # Task instructions for this phase
│   │   ├── TASKS.md           # Per-phase task checklist
│   │   ├── REASONING.md       # Agent's decision log for this phase
│   │   ├── ANALYSIS.md        # Optional: findings/analysis output
│   │   └── WALKTHROUGH.md     # Phase completion summary (generated by agent)
│   ├── n2/
│   │   └── ...
```

### File Descriptions

| File | Purpose | Created By |
|------|---------|------------|
| `META.json` | Pipeline metadata — immutable after creation, status updated per phase | `h-pipeline` / API |
| `pipeline.json` | Runtime status — updated by executor on every state change | Executor agent |
| `TASKS.md` | Phase-level progress indicator | Pipeline creator |
| `pipeline-flow.json` | DAG topology — agents, prompts, phase dependencies | Flow Builder |
| `builder-layout.json` | Visual layout — x/y positions, edge type, animation | Flow Builder UI |
| `phases/<id>/IMPLEMENTATION.md` | Phase instructions for the agent | Pipeline creator |
| `phases/<id>/TASKS.md` | Phase subtask checklist | Phase agent |
| `phases/<id>/REASONING.md` | Agent's decision log | Phase agent |
| `phases/<id>/WALKTHROUGH.md` | Phase summary with outputs | Phase agent |

## Phase Execution (Topological Sort)

Phases have an explicit `order` array in `pipeline-flow.json`:

```json
{
  "order": ["n1", "n2"],
  "phases": {
    "n1": { "agentId": "hermes-nous", "label": "Analyze", "order": 1 },
    "n2": { "agentId": "opencode-developer", "label": "Document", "order": 2 }
  }
}
```

For DAG topologies, the executor:
1. Reads `builder-layout.json` edges (source → target)
2. Computes topological sort
3. Spawns ready nodes (no uncompleted dependencies)
4. Cascades to next ready nodes as each completes
5. Supports `retry` and `skip` per-phase via API

## Flow Builder UI

The dashboard Pipeline Builder (at `/pipelines/builder`) provides:
- **DAG editor** — drag-and-drop agent nodes with React Flow
- **Phase assignment** — pick agent, write prompt, select skills/MCPs
- **Edge wiring** — draw dependency edges between nodes
- **Layout persistence** — saves `builder-layout.json` with node positions
- **Execution** — `POST /api/pipelines/:id/execute-flow` reads the DAG and runs topological sort

See [screenshots/](../docs/screenshots/) for builder UI screenshots.

## Agent Dispatch

Each phase spawns the assigned agent with:
- `IMPLEMENTATION.md` as the task prompt
- Pipeline directory path as workspace
- Shared context from `memory/shared/context.md`
- `shared-memory` MCP tools for reading ledger, sending messages, updating status

Agents communicate back via:
- Writing artifacts to `phases/<id>/`
- Updating `pipeline.json` status
- Sending inbox messages to other agents

## CLI Reference

| Command | Function |
|---------|----------|
| `h-pipeline submit` | Submit a cross-agent pipeline plan |
| `h-pipeline list` | List all pipelines |
| `h-pipeline status <id>` | Show pipeline status |
| `h-pipeline execute <id>` | Execute a pipeline |
| `paos-pipe-id` | Generate next PIPE-ID |
| `paos-pipeline-handler.sh` | Systemd-triggered handler for new submissions |
| `paos-pipeline-watch.sh` | Fallback inotify watcher (containers/WSL) |
| `paos-queue` | FIFO pipeline queue management |

## API Endpoints

See [api.md](api.md#3-pipelines) for full endpoint reference:
- `GET /api/pipelines` — list pipelines
- `POST /api/pipelines` — create pipeline
- `GET /api/pipelines/:id` — pipeline detail
- `POST /api/pipelines/:id/execute` — linear execution
- `POST /api/pipelines/:id/execute-flow` — DAG execution with topological sort
- `GET /api/pipelines/:id/flow-status` — real-time DAG status
- `POST /api/pipelines/:id/intervene` — pause/resume/edit
- `POST /api/pipelines/:id/phases/:phase/retry` — retry a failed phase
- `POST /api/pipelines/:id/phases/:phase/skip` — skip a phase
- `DELETE /api/pipelines/:id` — delete pipeline
